# Два сайта для предложения бизнесу

Это два отдельных приложения с разным дизайном, собственными базами данных, регистрацией, записью и админкой:

| Приложение | Компания | Локальный адрес |
|---|---|---|
| `mori-cuts/` | Mori Cuts, Торонто, Канада | http://127.0.0.1:8771 |
| `buffalo-barbershop/` | Buffalo Barbershop, The Villages, Флорида | http://127.0.0.1:8772 |

## Быстрый запуск

Нужен **Node.js 24+**. Установка пакетов не требуется. Откройте папку нужного приложения и запустите `START.cmd` в Windows либо выполните `node server.mjs`. Затем откройте адрес из таблицы. Пока сервер работает, окно запуска должно оставаться открытым.

Сайт нельзя запустить простым открытием HTML: аккаунты, услуги и запись получают данные с сервера.

## Доступ администратора

В папке приложения запустите `OWNER.cmd` или `node owner.mjs`. Укажите своё имя, email и новый пароль длиной 12–128 символов. Вход пароля в этой локальной консоли виден; запускайте её приватно. Не используйте этот инструмент для обычного клиента: он создаёт/восстанавливает именно администратора.

Войдите на `/account.html`, затем откройте `/admin.html`. Общего пароля, публичной кнопки создания админа и встроенной учётной записи нет. В архивы не входят тестовые аккаунты и базы.

## Что реализовано

- Регистрация, вход, выход, семидневные серверные сессии и смена пароля с завершением старых сессий.
- Кабинет клиента: список заявок, статусы, сохранённая цена и отмена будущей записи.
- Выбор услуги, мастера, даты и времени. Часовой пояс бизнеса показан явно.
- Сервер проверяет интервалы работы, длительность услуги и пересечения; занять пересекающиеся слоты нельзя.
- Админка: создание/редактирование/скрытие услуг и мастеров, настройка датированных рабочих интервалов и перерывов, подтверждение/отмена/завершение записей, поиск, фильтр статусов, список клиентов, CSV и журнал действий.
- Загрузка разрешённых фотографий JPEG/PNG/WebP до 5 МБ, alt-тексты, подписи, галерея и привязка портрета к мастеру.
- Сохранение данных SQLite, резервное копирование, восстановление доступа через серверную консоль.
- Адаптивные страницы, клавиатурный фокус, мобильная навигация, семантические формы и reduced motion.

Админка сохраняет данные **в базе**, а не в localStorage. Обновления видны на сайте после перезагрузки. Новые заявки появляются после кнопки Refresh dashboard. График задаётся отдельно на каждую дату, а не повторяющимися недельными правилами.

## Как показать потенциальному покупателю

1. Запустите сайт. Создайте администратора и отдельный тестовый клиентский аккаунт.
2. Через клиентский аккаунт выберите услугу и отправьте демо-заявку.
3. Войдите как администратор в другом профиле/браузере и подтвердите заявку.
4. Покажите клиенту изменение статуса, затем управление ценой, фотографиями и расписанием.
5. Обсудите с владельцем реальный способ записи: пользоваться этой системой как единственным расписанием либо оставить запись через Booksy. Автоматической синхронизации с Booksy нет.

## Важные границы готовности

Это работающие приложения для демонстрации и дальнейшей передачи бизнесу. Они **не являются уже внедрёнными официальными сайтами компаний**. Отдельные собственные сайты не найдены в проверенных источниках; отсутствие не доказано. Подробности — в `RESEARCH.md` и на странице About каждого сайта.

Цены и имена мастеров опубликованы в Booksy. Фотография интерьера лицензирована, но не относится к этим бизнесам; подпись это объясняет. Фотографии работ, портреты и актуальный прайс нужно получить/подтвердить у владельца. Email/SMS-уведомления, верификация email, автоматическая email-восстановление пароля, платежи и синхронизация внешнего календаря **не подключены**. Записи принимаются как заявки с ручным подтверждением.

## Публикация и передача

**GitHub Pages не запускает серверную часть.** Для этих проектов нужен хостинг Node.js с постоянным диском либо Docker/VPS. Не выдавайте публикацию одной папки `public/` за работающий сайт с регистрацией.

Для контейнера предусмотрен Dockerfile. Пример локального демо:

```sh
docker build -t barber-app .
docker run --rm -p 8080:8080 -e PUBLIC_ORIGIN=http://localhost:8080 -v barber-data:/data barber-app
```

У каждого бизнеса должен быть **отдельный** том данных. Веб-страницы, API и cookie обслуживаются с одного домена. При использовании reverse proxy сохраняйте Origin; приложение сравнивает его с `PUBLIC_ORIGIN`. Не доверяйте заголовкам произвольных клиентов для определения исходного IP.

После письменного согласования владельцем, проверки контактов и готовности расписания можно включить режим работы с реальными заявками:

```text
HOST=0.0.0.0
PORT=8080
DATA_DIR=/data
PUBLIC_ORIGIN=https://ВАШ-РЕАЛЬНЫЙ-ДОМЕН
APP_MODE=live
OWNER_APPROVED=yes
```

Это переменные окружения хостинга; файл `.env` автоматически не читается. Без HTTPS-origin и `OWNER_APPROVED=yes` live-сервер не запускается. В live-режиме демо-слоты и демо-заявки не используются: добавьте реальные рабочие интервалы в админке. Настройте HTTPS на reverse proxy. В live-заявках остаётся ручное подтверждение.

Перед официальным запуском:

- Получить согласованные контакты, цены, длительность, услуги каждого мастера, график и фотографии; определить налоги и доплаты.
- Отредактировать публичные тексты и обозначение независимого превью, добавить юридического оператора, privacy-контакт и политику хранения/удаления данных.
- Решить процедуру восстановления доступа, подтверждения email и уведомлений; не обещать автоматические сообщения до подключения сервиса.
- Определить единое расписание с учётом телефонных и Booksy-записей. Встроенное предотвращение конфликтов видит только записи в этой базе.
- Настроить постоянный диск, отдельного администратора, резервные копии, мониторинг, ограничения доступа на сервер и проверку на физических устройствах.
- Для официального SEO добавить домен в canonical/og:url, социальное изображение, sitemap и подтверждённую LocalBusiness-разметку; убрать `noindex,nofollow` и запрет `robots.txt`. Сейчас индексация выключена, чтобы не подменять официальный бизнес.

## Обслуживание

`node backup.mjs` создаёт согласованный снимок SQLite и копию загруженных фотографий в `data/backups/<дата>/`. Во время резервного копирования изображений не загружайте новые файлы; вынесите копию на отдельное защищённое хранилище. Для восстановления остановите сервер и восстановите `shop.sqlite` и `uploads/` из одной копии. Не публикуйте `data/` и резервные копии в GitHub.

`node recover.mjs` сбрасывает пароль существующего аккаунта, не меняя его роль, и завершает старые сессии. Сначала подтвердите личность клиента вне этого инструмента. Самостоятельное удаление аккаунта не реализовано: запросы обрабатывает оператор через базу согласно согласованной политике.

В основе защиты: scrypt с индивидуальной солью, HttpOnly/SameSite cookie (Secure при HTTPS), CSRF-токены и проверка Origin, проверки ролей на сервере, параметризованные SQL-запросы, ограничение попыток входа, CSP и проверка типа загрузок. Это не внешний аудит безопасности. При нескольких репликах понадобится отдельная архитектура хранения, сессий и лимитов; текущая версия рассчитана на один процесс с локальным постоянным диском.

## Проверка

Для обоих проектов прошли интеграционные проверки регистрации, авторизации, CSRF/Origin, изоляции клиентов, конфликтующих заявок, длительности, смены статусов, сохранения первоначальной цены, интервалов, загрузок, смены пароля и сохранения базы после перезапуска. Выполнены проверки доступности файлов и запрета доступа к приватным файлам. Через браузер пройдены регистрация → заявка → подтверждение в админке; выполнены визуальные проверки главных страниц и адаптивности. Подробности — `QA.md`.
